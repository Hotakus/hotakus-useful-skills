# Windows 磁盘空间清理

在 Windows 上诊断磁盘占用、释放空间时，必须严格遵循以下准则。目标是在不破坏用户数据与可复现环境的前提下，把空间收回来。

**前置条件**：执行任何删除动作前，必须完整阅读本规范并逐条对照。

## 1. 为什么需要这些规则

磁盘清理的失败模式只有两类：**删错东西**和**白删一通**。前者破坏环境，后者让用户以为空间已回收、实际没有。

本规范的核心假设是：磁盘上绝大多数体积属于不可再生的用户数据与已安装程序。可安全删除的部分集中在缓存、临时文件和构建产物，而这三类的边界因工具而异，必须逐个验证而非凭经验归纳。

## 2. 规则 1：先测量后决策

**在完成容量扫描之前，禁止删除任何文件。**

扫描顺序固定为：盘符总容量 → 顶层目录体积 → 用户目录体积 → AppData 两级明细 → 临时目录明细。每一步按体积降序排列，只对排名靠前的目录展开下一级。

理由：凭目录名猜测占用会漏掉真正的体积大户。Windows 上最常见的误判是把注意力放在 `C:\Windows`，而实际占用集中在用户目录下的应用数据里。

**正确**：

```bash
# 逐层下钻，每层按体积排序取前 20
du -sm /c/* 2>/dev/null | sort -rn | head -20
```

**错误**：

```bash
# 未扫描直接按经验删缓存目录 —— 删错对象的概率高
rm -rf "$LOCALAPPDATA/npm-cache"
```

## 3. 规则 2：用户约束优先于清理清单

**执行删除前，必须先向用户取得「哪些内容不许动」的明确清单，并把该清单写在执行计划的首位。**

用户会明确排除正在使用的浏览器缓存、需要保留的 IDE 插件、特定的开发工具。这些排除项高于本规范第 10 节风险分级表的任何条目。

**正确**：

```text
执行计划：
排除项（用户指定，不碰）：浏览器缓存、IDE plugins 目录
待清理：超过 24 小时的临时文件、GPU 着色器缓存、包管理器缓存
```

**错误**：

```text
按风险分级表清理全部「安全」级别目录
（忽略用户已说明的排除项，把它们也纳入清理范围）
```

## 4. 规则 3：只删可再生数据

**只删除能够由程序重新生成的缓存与临时文件。插件目录、用户文档、已安装包、程序本体一律不删。**

判定标准：删除后重新启动对应程序，该内容会自行重建且功能不受影响。

例外：包管理器的 store 目录允许通过管理器自带的 `prune` 子命令清理未引用包，禁止直接删除 store 目录本身。

**正确**：

```bash
# 通过包管理器自身的回收机制
pnpm store prune
```

**错误**：

```bash
# 直接删除 store 目录 —— 破坏所有依赖该 store 的项目链接
rm -rf "$LOCALAPPDATA/pnpm/store"
```

## 5. 规则 4：提权只用于删除动作

**扫描、统计、查看一律使用普通权限；仅删除动作申请提权。**

文件沙箱环境下，写入工作区外的路径会返回 `EPERM`，删除动作必须显式申请更宽的文件权限。

**正确**：

```text
扫描：普通权限执行体积统计
删除：申请完整访问权限后执行删除
```

**错误**：

```text
整个流程一次性申请完整磁盘权限
（扩大了误删的影响范围）
```

## 6. 规则 5：时间过滤保护活跃文件

**批量清理临时目录时，必须按修改时间过滤，禁止整体清空。**

正在安装的程序、正在运行的构建任务会在临时目录写入活跃文件，整体清空会中断它们并留下损坏状态。

**正确**：

```bash
# 只删修改时间超过 1440 分钟（24 小时）的条目
find "$TEMP" -mindepth 1 -maxdepth 1 -mmin +1440 -exec rm -rf {} + 2>/dev/null
```

**错误**：

```bash
# 整体清空 —— 会打断正在进行的安装与构建
rm -rf "$TEMP"/*
```

## 7. 规则 6：每步复检体积并记录失败项

**每个清理动作执行后，必须立即重新测量目标目录体积，并统计成功与失败项数量。**

占用中的文件、权限受限的目录会删除失败。失败项数量必须如实报告，不能省略。

**正确**：

```text
临时目录：5843MB → 1488MB，626 项成功 / 35 项失败（占用或权限）
```

**错误**：

```text
临时目录已清理完毕
（未复检、未统计失败项，用户无法判断是否真的回收了空间）
```

## 8. 规则 7：系统目录走系统工具

**系统目录与系统文件禁止手工删除，必须通过对应的系统工具处理。**

| 对象 | 处理方式 |
|---|---|
| 组件存储 `WinSxS` | `DISM /Online /Cleanup-Image /StartComponentCleanup` |
| 分页文件 `pagefile.sys` | 通过系统属性或 `wmic pagefileset` 调整 |
| 休眠文件 `hiberfil.sys` | `powercfg /hibernate off` |
| 系统更新残留 | 磁盘清理工具的「清理系统文件」功能 |

**正确**：

```text
使用 DISM 清理组件存储中的旧组件
```

**错误**：

```text
直接删除 C:\Windows\WinSxS 下的目录 —— 破坏组件存储，系统更新与卸载失效
```

## 9. 规则 8：报告必须提供前后对比

**清理结果必须以表格形式给出清理前后的体积对比与总回收量。**

用户需要据此判断是否达成目标、是否需要继续下一轮。

| 项目 | 清理前 | 清理后 | 回收 |
|---|---|---|---|
| 临时文件 | A | B | A−B |
| 着色器缓存 | C | D | C−D |
| 包管理器缓存 | E | F | E−F |
| **总计** | … | … | **合计** |

## 10. 风险分级速查

| 级别 | 对象 | 执行要求 |
|---|---|---|
| **安全** | 浏览器缓存、GPU 着色器缓存、包管理器缓存、超过 24 小时的临时文件、崩溃转储、缩略图缓存 | 取得用户批准后可直接删除 |
| **谨慎** | IDE 的 system 目录（仅删除 `caches`、`index`、`log` 子目录）、包管理器 store（仅用 `prune`）、回收站、超过 1GB 的临时目录 | 删除前确认路径归属并检查进程占用 |
| **禁止** | `WinSxS` 手工删除、`Installer` 目录、插件目录、用户文档、`Program Files` | 不执行任何删除动作 |

## 11. 常见缓存位置

路径变量：`%LOCALAPPDATA%` = `C:\Users\<用户>\AppData\Local`，`%APPDATA%` = `C:\Users\<用户>\AppData\Roaming`。

| 类别 | 常见路径 |
|---|---|
| 浏览器缓存 | `%LOCALAPPDATA%\<浏览器>\User Data\Default\Cache` |
| GPU 着色器缓存 | `%LOCALAPPDATA%\NVIDIA\DXCache`、`%LOCALAPPDATA%\NVIDIA\GLCache` |
| 包管理器缓存 | `%LOCALAPPDATA%\npm-cache`、`<包管理器> store path` 命令输出的路径 |
| IDE 缓存 | `%LOCALAPPDATA%\JetBrains\<产品>\caches`、`%APPDATA%\Code\CachedExtensionVSIXs` |
| 崩溃转储 | `%LOCALAPPDATA%\CrashDumps` |
| 临时文件 | `%TEMP%` |
| 回收站 | 各盘符根目录下的 `$Recycle.Bin` |

## 12. 进程与占用探测

删除前必须先确认目标目录没有被运行中的进程占用。

| 目的 | 命令 | 说明 |
|---|---|---|
| 列出运行中的进程 | `Get-Process` | 受限环境下可用 |
| 按名称查进程 | `Get-Process -Name <名称>` | 判断某程序是否在运行 |
| 探测目录占用 | 尝试删除，失败项单独统计 | 占用中的文件会删除失败 |

`tasklist`、`Get-CimInstance` 在受限沙箱环境中会被拒绝访问（拒绝访问错误），改用 `Get-Process`。

## 13. 禁止事项

- 禁止在扫描完成前删除任何文件
- 禁止删除用户已明确说明不许动的内容
- 禁止手工删除 `WinSxS`、`Installer`、插件目录
- 禁止整体清空临时目录
- 禁止直接删除包管理器 store 目录
- 禁止把删除失败的项当作成功计入回收量
- 禁止只报告「已清理」而不给具体体积数字

## 14. 自检要求

输出清理方案或执行结果前，逐项核查：

- [ ] 是否已完成容量扫描并给出分层占用数据？
- [ ] 是否已取得用户的排除项清单并写入计划？
- [ ] 每个待删对象是否属于可再生数据？
- [ ] 批量删除是否带有时间过滤？
- [ ] 删除动作是否单独申请了权限？
- [ ] 每个动作后是否复检了体积并统计了失败项？
- [ ] 系统目录是否交由系统工具处理？
- [ ] 报告是否包含前后对比表与总回收量？
